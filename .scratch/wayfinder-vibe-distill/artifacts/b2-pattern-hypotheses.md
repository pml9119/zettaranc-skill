## 三、🔴 换手率假说的**修正**（含本轮实测反例）

### 3.1 原假说

> 「换手率是分水岭：缩量（≈5）是洗盘，放量（>17）是出货——京北方就是反例。」

### 3.2 反例（本轮实测，可复跑）

| 股票 | 模式 | 图注 换手 MA1 | 相对量能 `vol/MA(vol,5)` | 结果 |
|---|---|---|---|---|
| **指南针** `300803.SZ` 2025-06-24 | **A** | **18.49（放量）** | **2.71x** | **+44.32%** |
| 京北方 `002987.SZ` 2025-06-16 | **D** | 17.09（放量） | 1.91x | +0.71% |

**两个都是「放量」，结果相反** → 「换手率 > 17 = 出货」作为**单变量规则被证伪**。

### 3.3 修正后的假说 **H1（交互效应）**

> 量能对后续收益的作用，**符号取决于位置**：
> - **低位 / 平台突破 + 放量 → 正**（突破需要量能确认）
> - **高位 + 放量 → 负**（出货）

**H1 的可检验形式**：

```
因变量  ret  = 信号日后 20 个交易日收益（固定窗口，避免长度不可比）
自变量  vr   = vol / MA(vol, 5)          # 相对量能（不需要股本数据）
        pos  = close / max(high, 60)     # 位置分位
模型    ret ~ vr * pos
核心预期 交互项系数 < 0（vr 的正效应随 pos 升高而衰减并转负）
```

### 4.2 🔴 F4 已实测解决：**`vol` 单位按板块分裂**

全市场实测（`20250716`，5,139 只，判据 = `vol` 与 `daily_valuation.turnover`、`float_share` 的一致性）：

| 板块 | 按【手】吻合 | 按【股】吻合 | 都不吻合 |
|---|---|---|---|
| **688 科创板** | 0 | **588** | **0** |
| 300 / 002 / 600 / 603 / 301 / 000 / 601 / 605 / 001 / 003 | **4550** | 0 | **0** |
| **汇总** | **4550** | **589** | **0** |

> **结论：`daily_kline.vol` 的单位 = 科创板(688) 是「股」，其余板块是「手」。差 100 倍。**

这正是 `tdx-formula-mapping.md` 标注的**最高风险阻塞项 ③（VOL 单位须实测）**。

**换算公式**：`turnover(%) = vol × 100 ÷ (float_share × 10000) × 100`（vol 为手时）

### 4.3 影响面：当前代码**几乎零风险**，但是潜伏 bug

逐项排查 `modules/` 全部 `kline.vol` 用法：

| 用法 | 位置 | 是否受影响 |
|---|---|---|
| 量比 `current_vol / avg_vol` | `core.py:845-851`、`volume_patterns.py:48` | ❌ **不受影响**（比值，100 倍抵消） |

| **砖型图公式** | `brick.py` | ❌ **完全不用 vol**（已核验） |
| 绝对阈值比较（`vol > 常量`） | 全仓扫描 | ❌ **0 处** |
| 跨股票 vol 排序/比较 | 选股引擎 | ❌ 0 处 |

→ **当前所有用法都是同股内比值，100 倍自动抵消。**

**但风险是潜伏的**：任何**未来**代码只要做以下任一件事就会静默错 100 倍（仅对 688）：
1. 跨股票比较 vol（如"全市场量比排名"）

**➡️ 建议**：在**数据层归一化**（688 的 `vol ÷ 100` 转成手），下游全部统一。
**理由**：因为当前所有用法都是比值，**归一化不改变任何现有结果**（可零风险验证）；而 F3 过滤器（ticket 02 下一步）**必然要用成交量**，不先修就会踩雷。

## 九、砖型图组：**模式 E · 砖底黄转红**

### 9.1 ★ 用户裁定：**黄砖 = 「砖买入」信号** → 三态已实现（commit `0a538b4`）

| 状态 | 值 | 含义 |
|---|---|---|
| 绿 | `BRICK_GREEN` = **-1** | 砖值 < 前一日（下跌动量） |
| **黄** | `BRICK_YELLOW` = **0** | **★ 砖买入信号** —— 砖值**由降转升的转折点**（第一块红砖） |
| 红 | `BRICK_RED` = **+1** | 砖值 ≥ 前一日（上涨动量） |

**依据链（四条独立证据）**：

1. **语料规则**：`[20260325] 回放3 00:02:48`「定式一就是 N 型起跳…每次都要买到**转折点这个位置的红砖**」；`00:40:36`「**红砖的第二块儿的早盘买入**」
2. **知识库**：`strategies/choppy-market-sop.md:197`「**绝不在绿砖阶段买入**：等红砖再动」
3. **语料中「黄砖」0 命中** → **黄是软件的呈现色，不是语料术语**
4. **9 张砖型图参考图的十字线 9/9 全部满足** `brick[i] >= brick[i-1] and brick[i-1] < brick[i-2]`

**→ 关键结论**：**我们的 `calculate_brick_series` 本来就把转折点定位对了，缺的只是渲染态**（后端只产 ±1，黄砖数学上不可达）。

**连带解决两个悬案**：
- 砖色子代理怀疑的「**9/9 全黄可能是竖线伪影**」→ **不是伪影，是买入信号**
- 形态子代理的**假说 H1**（十字线标的是砖型图信号而非 B1 信号）→ 从 **7/9 弱支持升级为 9/9 支持**

### 9.3 ★ 用户裁定：**砖型图的形态必须结合主图判定**

**砖序列不能单独使用。** E-1 / E-2 的划分**正是靠主图的价格位置**（收盘在多空线之上/之下）区分的 —— 与用户裁定一致。

### 9.4 与 B2 的 A/B/C/D 的关系

```
砖型图 E-1（深调启动）   ←同构→  B2 的 A（底部/平台突破启动）
砖型图 E-2（上涨段回踩） ←同构→  B2 的 B（上升趋势中回踩多空线）

```

**方向同构、判据不同构**：可共用「位置」维度（底部/中继/高位），但**入场判据必须各自独立**。
