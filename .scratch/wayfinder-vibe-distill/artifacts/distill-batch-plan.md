## 一、批次划分原则

1. **一批 = 一个模块内的一个连贯主题**，段数 8–14（约 1M 字符以内，单子代理可完成）。
2. **一场次可服务多个模块** → 必要时在不同批次重复出现（多标签，承 01 v3 结论）。
3. **🚨 语料读取策略（2026-09-11 定案：`transcript.txt` 为主，`notes.md` 仅作定位索引）**

   > **废止旧策略**：`distill/PIPELINE_STATE.md` 中「notes.md 优先，transcript.txt 补缺」**作废**。

   | 角色 | 文件 | 用途 |
   |---|---|---|
   | **主源（唯一引文来源）** | `transcript.txt` | 事实、引文、时间戳 —— **一切断言以它为准** |
   | **辅源（仅导航）** | `notes.md` | **只读小节标题 + 时间范围**用于定位，**不作事实来源** |
   | **弃用** | 推理稿型 `notes.md` | 17 个文件整篇不可用 |

   **逐段读取规程（每批照此执行）**：
   ```
   0. ★ 查 artifacts/corpus-coverage-risk.tsv（291 段全量排查，含两级修正）：
        等级 A （整篇推理稿，10 段）  → 直接全文读 transcript，notes 完全弃用
        等级 A2（几无时间戳，5 段）    → 同上，通读 transcript
        等级 B （覆盖 <80%，18 段）   → 以 transcript 为准通读全文，notes 仅交叉校验
        等级 A1（首行有回声，19 段）  → ★【照常走原规程】，仅跳过开头 1–3 行
        等级 OK（239 段）            → 走下面原规程
   1. 只读 notes.md 的【小节标题 + 时间范围】建导航表（跳过正文）
   2. 按导航表精读 transcript.txt 对应时间窗
   3. 检索关键词必须带 ASR 变体表（否则 notes 漏 14.2% / transcript 漏 32.3%）
   4. 引文一律取 transcript，标 `回放N HH:MM:SS`
   5. 未听清处照录并加〔〕标注，禁止静默改写
   ```
   **★ 为什么加第 0 步**：全量排查实测 **52 段（17.9%）需特殊处理** —— A1 撞到的 `20251015 回放3`（notes 覆盖率 **9.4%**）**不是孤例**。
   **⚠️ 关键区分**：**A 类（10 段，真·草稿，标题数=0）与 A1 类（19 段，成品笔记仅首行污染）处置完全不同** —— 前者弃用 notes，后者**照常导航**。（此分级经两轮修正，v1 曾把两类混为一谈、高估 7 段。详见 `corpus-read-risk-scan.md`。）
   **成本影响**：含 **A/A2/B** 类段的批次须通读 transcript → 从「8–14 段」降为 **「5–8 段」**；**含 A1 类的不受此限**。
   **五条原依据**（全部实测）：① `notes.md` 是 LLM 从 transcript **二次生成的派生品**（10 篇真·推理稿即铁证）② 引文规范要求逐字+精确时间戳，**notes 的分段区间不是精确时间戳** ③ 推理稿连导航价值都没有 ④ ASR 变体两源都要面对，属检索问题非选源问题 ⑤ transcript 21.5MB vs notes 4.7MB（4.6×）→ 用 notes 定位、只精读 transcript 对应窗口，成本可控（03 试点即此法）。
   **对已有产物的影响**：A1/A2 **已完成 v2 重做**；03 v2 已是正确读法范例。
   → 详见 `new-materials-integration.md` §四、`corpus-read-risk-scan.md`
4. **每批必产出**：`PIPELINE_STATE.md`（断点）+ per-pool 蒸馏卡 + 合并能力卡（R/I/A1/A2/E/B 六段）+ 与 `knowledge/` diff。
5. **顺序按缺口严重度**，不按日期。
