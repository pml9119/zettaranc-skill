## 二、考试测试集（`20260429 三种常用战法摸底考`）——用什么形式加

### 2.1 它到底是什么（实测）

这不是一份「讲义」，而是**带标注的真值数据集**：每条 = `日期 + 代码 + 名称 + 判定 + Z 哥口述理由`。

| 项 | 实测 |
|---|---|
| 段落 | 131（正文区 133 行） |
| 图片 | 64 |
| 解析出的案例 | **65 条** |
| 带理由 | **62 条** |
| **标签分布** | **不买 25 ｜ 买 25 ｜ 不卖 7 ｜ 卖 4 ｜ 可买可不买 2 ｜ 空 2** |
| 图片对齐 | **成功** —— image N 紧随案例 N（`docx-image-map.tsv`） |
| 时间跨度 | 2024-10 → 2026-04 |

**为什么它比普通语料珍贵**：整个项目此前**没有任何人工标注的判定真值**。这套东西是 **Z 哥本人给 65 个真实案例打的标签**，覆盖**买/不买/卖/不卖双侧**（`不买` 与 `买` 各 25 条，是完美的对照）。

### 2.2 推荐形式：**双重身份 —— ① 验收集（eval set）② 案例库（E 段素材）**

#### 身份 ①：**验收集** —— 项目第一份客观准确率基准 ★最重要

现有 `modules/verify/` 只有**五项硬门**（Sharpe/Calmar/胜率/MaxDD/OOS-IS），全部是**回测出来的统计量**，**没有一条是「人工标注的判定对照」**。

加入这套后可以建立：

```
对 65 条案例，逐条跑 detect_all_strategies(ts_code, as_of=date)
  → 与 Z 哥标签比对
  → 得到混淆矩阵：命中 / 漏报 / 误报（分「买侧」与「卖侧」）
```

### 3.2 推荐形式：**「视觉直读 + 数据重建」双轨证据条目**

```yaml
- id: b1-ref-01
  code: 002940.SZ          # 昂利康
  date: 2025-07-11          # 形态判定日
  kind: B1                  # B1 / B2 / brick
  original_image: images/b1-ref-01.png      # Z 哥原图
  vision_read:                                # ① 视觉直读（我可直接产出）
    title: "昂利康(日线.前复权)"
    indicator_panel: {短期线: …, 多空线: …, BBI: …, KDJ: …}
    pattern: "…"                              # 形态的定性描述
    annotations: "…"                          # 图上的箭头/数字/文字标注
  rebuilt_image: rebuild/b1-ref-01.png       # ② 数据重建（modules/indicators 重画）
  window: 120
  verdict: pending                           # pending / match / mismatch
```

**为什么两轨都要**（各自补对方的短板）：

| 轨 | 拿到什么 | 补什么短板 |
|---|---|---|
| **① 视觉直读** | 指标面板数值、Z 哥的箭头/标注、形态的**定性**描述 | 拿到**数据里没有的**东西（人工标注、画线意图） |
| **② 数据重建** | 同一形态的**数值**（KDJ/白线/黄线的精确值、砖块计数） | 让形态**可复算、可回归**；视觉描述无法参与 CI |

**买到四件事**：
1. **可验证** —— 重建图与 Z 哥原图若指标数值一致 ⇒ **反向证明项目的 KDJ/白线/黄线/砖型图实现与 Z 哥软件口径一致**。这是当前**完全缺失**的一层校验（现有测试全是自造 fixture，见 `tests/conftest.py`）。
2. **可回归** —— 31 条**真实形态**远强于 `generate_uptrend_klines()` 合成数据，可作 `detect_b1`/`detect_b2`/`detect_brick_*` 的**真实样本回归集**。
3. **术语可对齐** —— 图上标题栏直接给出指标名与当前值（如「5日知行B1选 短期线:17.72 多空线:16.80」），可校准 `短期线`/`多空线` 等术语与仓库字段的对应。
4. **不依赖单一手段** —— 视觉直读受截图裁切影响（标题栏/日期轴可能被裁），数据重建可补；数据重建依赖 DB 覆盖，视觉直读可补。

### 3.3 与考试集的关系：**正例库 vs 混合判例库**

| 素材 | 标签 | 用途 |
|---|---|---|
| **B1/B2/砖型图参考图**（31 条） | **隐式正例**（"这些是标准形态"） | **召回基准**：探测器应当在这些上给出信号 |
| **考试测试集**（65 条） | **显式判定**（买/不买/卖/不卖） | **准确率基准**：含反例，能算误报 |

两者合用才完整：**只有正例 → 只能算召回；有反例 → 才能算精确率**。

### 3.4 不建议的形式

| 形式 | 为什么不 |
|---|---|
| OCR 提取图上文字 | tesseract 未装；**且 K 线形态不是文字，OCR 得不到形态** |
| 让 LLM 描述图 | 本会话读不了图；即便可读也**不可复现、易幻觉** |
| 只存图为「附件」不建索引 | 无法与 code+date 关联，等于死资料 |
| 直接把图当 `knowledge/` 文档 | `knowledge/` 是 md 文本，RAG 消费不了图 |

> **若确实需要「图上的标注/箭头」**（Z 哥画的线、圈、文字）：那属于像素级信息，**必须一次 vision pass** —— 本模型不可用。建议**先做重建**，比对后再决定是否值得为标注单独找人/换模型看一遍。

## 四、语料读取策略：**transcript.txt 为主，notes.md 仅作定位索引**

### 4.1 直接结论

| 角色 | 文件 | 用途 |
|---|---|---|
| **主源（唯一引文来源）** | `transcript.txt` | 事实、引文、时间戳 —— **一切断言以它为准** |
| **辅源（仅导航）** | `notes.md` | **只读小节标题 + 时间范围**，用于定位；**不作为事实来源** |
| **弃用** | 推理稿型 `notes.md` | 17 个文件整篇不可用（01 v3 §7.2） |

> **不是「notes 为主、transcript 补缺」，而是反过来。** 现有 `PIPELINE_STATE.md`（A2）写的是「notes.md 优先，transcript.txt 补缺」—— **该策略应废止**。

### 4.2 五条依据（全部实测）

1. **`notes.md` 是派生品，不是原始素材**。17/291 篇整篇是「我们need produce notes in Chinese markdown…」式的**生成推理稿** ⇒ 证明 `notes.md` 由 LLM **从 transcript 二次生成**。二手转述必然有遗漏与改写风险。
2. **引文规范要求逐字 + 精确时间戳**。03 试点已确立「引用格式 `回放N HH:MM:SS`（逐字稿行首时间戳）」，并明确指出 **notes 的分段标题区间「不可当作精确时间戳」**。只有 transcript 有行首时间戳。
3. **推理稿不可用**：17 篇（5.8%）`### [` 小节数为 **0**，全篇草稿且末尾截断 ⇒ 连「导航」价值都没有。
4. **ASR 变体造成的漏检，两源都需面对**（notes 14.2% / transcript 32.3%）—— 这不是选主源的理由，而是**检索必须带变体表**的理由（01 v3 §3.5）。
5. **成本可控**：transcript 21.5 MB vs notes 4.7 MB（**4.6×**）。若全文读 transcript 成本高，就用 `notes.md` 的**标题+时间范围**做索引，**只精读 transcript 的对应时间窗** —— 这正是 03 试点实际采用的做法，且效果良好。

### 4.3 建议写入 05 的**逐段读取规程**

```
对每一段（session/segment）：
  1. 若该段在 corpus-notes-quality.tsv 中等级 = 「整篇推理稿」
        → 直接全文读 transcript.txt（notes 完全弃用）
  2. 否则
        a) 只读 notes.md 的【小节标题 + 时间范围】建立导航表（跳过正文）
        b) 按导航表，精读 transcript.txt 对应时间窗
        c) notes 正文**可选**作为交叉校验；与 transcript 冲突时**以 transcript 为准并记录冲突**
  3. 检索关键词时**必须带 ASR 变体表**
  4. 引文一律取自 transcript，标 `回放N HH:MM:SS`
  5. 不确定/未听清处照录原文并加〔〕标注，**禁止静默改写**
```

### 4.4 对已有产物的影响

- **A1 / A2 需复核**（05 v2 已记）：它们用过推理稿件，且当时误诊为「notes 截断」→ 现应改为「transcript 重读」。
- **03 试点 v2 已是正确读法的范例**（它发现推理稿后改以 transcript 为主源）。
- `distill/PIPELINE_STATE.md` 中「notes.md 优先」的策略句**应改写**。
